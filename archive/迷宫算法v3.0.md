# 迷宫生成方案 v3.0 - 自顶向下区域式生成

## 一、方案概述

将100×100格的大地图先划分为10×10个区域（每个区域10×10格），在大结构层面确定区域连通关系和类型，再细化每个区域内的具体地形。

**优势**：玩家能感知到"穿越不同区域"的体验，迷宫有节奏感，多路径增加策略性。

---

## 二、全局参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 大地图尺寸 | 100×100格 | 总网格 |
| 区域划分 | 10×10个区域 | 每个区域10×10格 |
| 区域大小 | 10×10格 | 单个区域的网格尺寸 |
| 起点终点最小距离 | 曼哈顿距离≥2 | 至少隔一个区域 |
| 主路径数量 | 1条主干道 + 1-2条替代路径 | 保证多路径 |
| 封闭区域比例 | 约20% | 只有1-2个入口的区域 |

## 三、阶段一：划分区域并确定起点终点

### 3.1 数据结构

```
// 区域数据结构
Region {
    id: string,              // 如 "region_3_5" 表示第3行第5列
    row: number,             // 0-9
    col: number,             // 0-9
    type: string,            // 阶段三分配，先留空
    connections: {           // 与相邻区域的连接关系
        top: boolean,        // 上方是否有连接
        bottom: boolean,     // 下方是否有连接
        left: boolean,       // 左方是否有连接
        right: boolean       // 右方是否有连接
    },
    entrances: [],           // 具体入口格子在边界上的位置，阶段四填充
    exits: []                // 具体出口格子在边界上的位置，阶段四填充
}

// 大地图数据结构
WorldMap {
    regions: Region[10][10], // 10×10区域矩阵
    startRegion: {row, col}, // 起点所在区域
    endRegion: {row, col}    // 终点所在区域
}
```

### 3.2 算法步骤

**步骤1：初始化区域矩阵**
```
创建 10×10 的 Region 数组
每个 Region 的 connections 初始化为 {top: false, bottom: false, left: false, right: false}
边界区域的对应方向强制为 false（如第0行的 top 都为 false）
```

**步骤2：选择起点区域**
```
startRow = 随机 0-9
startCol = 随机 0-9
约束：起点区域不在地图最中心（避免 row=4或5 且 col=4或5）
```

**步骤3：选择终点区域**
```
endRow = 随机 0-9
endCol = 随机 0-9
约束：
  |endRow - startRow| + |endCol - startCol| >= 2  （曼哈顿距离至少为2）
  endRow 不在大地图边缘（0或9），endCol 不在边缘（0或9）
  这样终点不会紧贴大地图边界
```

**步骤4：标记特殊区域**
```
startRegion = {row: startRow, col: startCol}
endRegion = {row: endRow, col: endCol}
```

## 四、阶段二：生成区域级通路

### 4.1 数据结构

```
// 区域通路图
RegionGraph {
    nodes: Region[10][10],
    adjacency: boolean[10][10][4]  // [row][col][direction] 方向：0=上 1=下 2=左 3=右
}
```

### 4.2 算法步骤

**步骤1：生成主干道（主路径）**

从起点区域出发，用带权重的随机游走生成一条通往终点区域的主路径。

```
currentRow = startRow
currentCol = startCol
mainPath = [{row: currentRow, col: currentCol}]

循环直到 currentRow == endRow 且 currentCol == endCol：
    1. 收集当前区域的四个邻居方向
    2. 排除：已访问的方向、大地图边界外的方向
    3. 为每个可选方向计算权重：
       - 朝向终点方向（减少曼哈顿距离）的权重 ×3
       - 保持当前方向（直走）的权重 ×2
       - 偏离终点方向的权重 ×1
    4. 按权重随机选择一个方向
    5. 在该方向上建立连接：
       currentRegion.connections[方向] = true
       邻居Region.connections[反方向] = true
    6. 移动过去，加入 mainPath
```

**步骤2：生成分支路径**

从主干道上的区域向外延伸分支。

```
对于 mainPath 上的每个区域：
    if 随机概率 < 0.4：  // 40%概率生成分支
        选择一个非主干道方向的邻居方向
        该方向建立连接
        向该方向延伸1-3个区域：
            每次延伸时：
                - 优先继续直走（权重×3）
                - 有30%概率停止延伸
                - 如果碰到大地图边界或已有连接的区域，停止
```

**步骤3：生成替代路径（回路）**

在起点和终点之间额外生成1-2条路径，形成回路。

```
loopCount = 随机 1-2

循环 loopCount 次：
    1. 从 mainPath 中间位置随机选一个区域作为回路起点
    2. 从 mainPath 另一个位置（离回路起点至少2个区域距离）选回路终点
    3. 用随机游走生成连接这两个区域的路径
    4. 这条路径上的连接不能和 mainPath 完全重合（至少有一些新区域）
```

**步骤4：生成封闭区域**

选择部分未连接或连接较少的区域作为封闭区域。

```
遍历所有区域：
    计算该区域当前的连接数（top+bottom+left+right中为true的数量）
    
    如果连接数 == 0：
        60%概率标记为封闭区域（后续只开放1个入口）
        40%概率随机连接到一个相邻区域
    
    如果连接数 == 1：
        50%概率标记为封闭区域（保持现状，不再增加入口）
        50%概率再开放一个入口（变成连接数2）
    
    如果连接数 >= 2：
        保持现状
```

**步骤5：开放封闭区域的入口**

```
对于标记为封闭区域的每个区域：
    如果当前连接数 == 0：
        随机选择1个方向开放连接
    如果当前连接数 == 1：
        保持不变（已经满足封闭条件）
```

**步骤6：验证可达性**

```
从起点区域出发，BFS遍历所有通过连接可达的区域
检查：
  - 终点区域必须在可达集合中（否则回到步骤3增加替代路径）
  - 从起点到终点至少有2条不同的路径（可以通过检查连接图是否有回路来验证）
  - 所有未被标记为封闭区域的区域都应该是可达的
```

**步骤7：输出**

每个 Region 的 connections 字段被填充完毕，表示该区域与相邻区域的连通关系。

## 五、阶段三：为每个区域分配类型

### 5.1 区域类型定义

| 类型 | 判定条件 | 内部特征 |
|------|----------|----------|
| start | 包含起点 | 简单开阔，通道稀疏 |
| end | 包含终点 | 有明显地标结构 |
| main | 在主干道上 | 通道较直，岔路少 |
| branch | 在分支路径上 | 蜿蜒，死胡同多 |
| junction | 多条路径交汇处 | 通道密集，回路多 |
| closed | 封闭区域 | 复杂，宝箱品质高 |

### 5.2 分配算法

```
遍历所有区域：
    if 区域是 startRegion：
        type = "start"
    else if 区域是 endRegion：
        type = "end"
    else if 区域在 mainPath 上：
        type = "main"
    else if 区域的连接数 == 1 且被标记为封闭区域：
        type = "closed"
    else if 区域的连接数 >= 3：
        type = "junction"
    else if 区域在分支路径上（不在 mainPath 上）：
        type = "branch"
    else：
        type = "main"  // 默认
```

### 5.3 输出

每个 Region 的 type 字段被填充完毕。

## 六、阶段四：细化每个区域内的地形

### 6.1 数据结构

```
// 单个格子
Cell {
    type: "wall" | "floor" | "special_wall" | "entrance" | "exit"
}

// 完整的100×100地图
Map {
    cells: Cell[100][100]
}
```

### 6.2 算法步骤

**步骤1：初始化完整地图**

```
创建 100×100 的 cells 数组
所有格子初始化为 "wall"
```

**步骤2：确定每个区域的边界开口位置**

根据每个 Region 的 connections，在对应边界上生成开口。

```
对于每个 Region（row, col）：
    if connections.top == true：
        在该区域的上边界（行起始位置 + 0）上：
            随机选择1-2个列位置作为开口
            开口宽度：1-3格（随机）
            记录到 entrances 或 exits 列表中
    if connections.bottom == true：
        在下边界（行起始位置 + 9）上同样处理
    if connections.left == true：
        在左边界（列起始位置 + 0）上同样处理
    if connections.right == true：
        在右边界（列起始位置 + 9）上同样处理

约束：
  - 同一方向如果有多个开口，它们之间至少间隔1格
  - 开口不要紧贴区域的四个角（留至少1格的边距）
```

**步骤3：在区域内生成迷宫**

对于每个区域，在其10×10网格内生成迷宫。**不是完整填充，只保证入口和出口连通。**

```
对于每个 Region（row, col）：
    1. 获取该区域内所有的入口和出口格子位置
       （这些格子在边界上，已经在上一步被标记）
    
    2. 将这些入口/出口格子的 Cell.type 设为 "floor"
    
    3. 使用 DFS 生成迷宫，但只从入口格子开始：
       - 从第一个入口出发，用随机DFS向区域内延伸
       - 每次随机选择一个未访问的邻居，打通墙壁，移动过去
       - 重复直到所有入口/出口相互连通
       - 不需要访问所有10×10个格子
       - 停止条件：所有入口和出口之间都存在通路
    
    4. 根据区域类型调整生成参数（见下方参数表）
```

**步骤4：区域类型的生成参数**

在DFS基础上，通过额外操作调整区域内部结构：

```
switch region.type：
    
    case "start"：
        - 额外打通墙壁：随机选择2-3面内部墙壁打通（制造开阔感）
        - 确保出口方向有明确的通道指向
    
    case "end"：
        - 终点位置：选择区域内距离入口最远的格子
        - 将该格子标记为 "exit"
        - 终点周围4格设为 "floor"（形成一个小房间）
        - 小房间有一个特殊的视觉标记（在地图上用不同颜色/符号）
    
    case "main"：
        - 通道直走权重 ×5（保持通道较直）
        - 死胡同数量：0-1个
        - 额外打通墙壁：0-1面
    
    case "branch"：
        - 通道直走权重 ×1（通道更蜿蜒）
        - 死胡同数量：2-4个
        - 在死胡同末端放置宝箱标记（阶段五处理）
        - 额外打通墙壁：0面
    
    case "junction"：
        - 通道直走权重 ×2
        - 死胡同数量：1-2个
        - 额外打通墙壁：2-4面（制造回路）
    
    case "closed"：
        - 通道直走权重 ×1（复杂蜿蜒）
        - 死胡同数量：3-5个
        - 额外打通墙壁：0-1面
        - 在死胡同末端和区域深处放置高价值宝箱标记
```

**步骤5：边界处理**

确保相邻区域的开口能够对接。

```
对于每对相邻的区域：
    它们在共享边界上的开口位置应该对齐
    （因为在步骤2中，当建立连接时，两个区域的对应边界上都会生成开口，
      所以开口位置应该一致）
    
验证：
    遍历共享边界上的每一格：
        如果一侧是 "floor"，另一侧也必须是 "floor"
        如果不一致，将两侧都设为 "floor"
```

**步骤6：最终验证**

```
从起点格子出发，BFS遍历所有 floor 格子
检查：
  - 终点格子在可达集合中
  - 所有宝箱标记所在的格子在可达集合中
  - 没有孤立的 floor 区域

如果有不可达的宝箱或孤立的 floor：
  - 在不可达区域和最近的可达 floor 之间打通最短路径的墙壁
```

### 6.3 输出

完整的100×100 Map，每个格子标记为 wall 或 floor。特殊位置（入口、出口、宝箱标记）也一并输出。

## 七、宝箱放置规则（在阶段四之后执行）

### 7.1 放置算法

```
遍历每个区域：

    if region.type == "start"：
        不放置宝箱
    
    else if region.type == "end"：
        在终点小房间内放置1个普通宝箱（作为通关奖励预览）
    
    else if region.type == "main"：
        在通道旁放置0-1个普通宝箱（位置不挡主路）
    
    else if region.type == "branch"：
        在死胡同末端放置1-2个宝箱
        其中50%概率为条件宝箱
    
    else if region.type == "junction"：
        散落放置1-3个宝箱
        位置在回路交汇处或通道交叉口
    
    else if region.type == "closed"：
        在深处和死胡同末端放置2-3个宝箱
        其中60%概率为条件宝箱，宝箱品质整体提升一级
```

### 7.2 宝箱类型

| 宝箱类型 | 内容 | 出现概率 |
|----------|------|----------|
| 普通宝箱 | 随机1个消耗型胶囊 或 小型火把补给 | 60% |
| 条件宝箱 | 需要消耗指定胶囊开启，内含更高品质奖励 | 25% |
| 豪华宝箱 | 直接开启，内含2个胶囊 或 大型火把补给 | 10% |
| 密室入口 | 不直接给奖励，而是标记附近有隐藏密室 | 5% |

## 八、完整生成流程伪代码

```
function GenerateFullMaze():

    // 阶段一：划分区域 + 起点终点
    regions = InitializeRegions(10, 10)
    startRegion = SelectStartRegion(regions)
    endRegion = SelectEndRegion(regions, startRegion)
    
    // 阶段二：生成区域级通路
    mainPath = GenerateMainPath(regions, startRegion, endRegion)
    GenerateBranches(regions, mainPath)
    GenerateAlternativePaths(regions, startRegion, endRegion, mainPath)
    GenerateClosedRegions(regions)
    ValidateRegionConnectivity(regions, startRegion, endRegion)
    
    // 阶段三：分配区域类型
    AssignRegionTypes(regions, mainPath, startRegion, endRegion)
    
    // 阶段四：细化区域内地形
    map = InitializeFullMap(100, 100, WALL)
    for each region in regions:
        PlaceBoundaryOpenings(region, map)
        GenerateInternalMaze(region, map)
    AlignBoundaries(map, regions)
    ValidateFullMapConnectivity(map, startRegion, endRegion)
    
    // 宝箱放置
    PlaceTreasureChests(map, regions)
    
    return map
```
