# 迷宫生成算法设计文档

## 一、算法目标

生成一个100×160格的多屏迷宫，使其具备：
- 区域化的探索节奏变化
- 充足的岔路和决策点
- 有意义的地标和发现体验
- 与火把系统、宝箱系统、战利品系统形成玩法协同

---

## 二、整体流程

迷宫生成分为五个阶段，按顺序执行：

1. 主干道骨架生成
2. 区域类型划分
3. 各屏迷宫生成（带参数控制）
4. 回路注入
5. 特殊元素放置（宝箱、出口、特殊地形）

下面逐一说明每个阶段的输入、输出和算法步骤。

---

## 三、阶段一：主干道骨架生成

### 3.1 目的

在大尺度上建立一张稀疏的“交通网络”，让玩家形成方向感和区域认知。主干道在后续展开时会被保留为较宽的通道。

### 3.2 输入

- 迷宫总尺寸：100行×160列（格子数）
- 单屏尺寸：10行×16列（格子数）
- 屏网格尺寸：10屏（纵向）× 10屏（横向）

### 3.3 算法步骤

**步骤1：构建粗网格**
- 将整个迷宫按屏为单位，视为一个10×10的粗网格
- 每个粗网格节点代表一屏（10×16格）

**步骤2：生成粗迷宫**
- 在10×10的粗网格上，使用Prim算法或Kruskal算法生成一个完美迷宫（每对节点之间有且仅有一条路径）
- 得到粗粒度的主干道连接关系：哪些屏与哪些屏之间有主干道连接

**步骤3：记录主干道边界**
- 对于每对相邻且有主干道连接的屏，记录它们共享的边界
- 边界是一条长为16格（横向相邻屏）或10格（纵向相邻屏）的线段
- 在后续展开时，这条边界上的墙壁将被移除至少2-3格宽，形成宽阔的主干道入口

**步骤4：确定主干道在地图中的位置（可选，但建议做）**
- 在粗迷宫中找到从起点所在屏到出口所在屏的唯一路径
- 这条路径上的屏，其主干道方向在展开时优先保留为直线延伸（减少主干道不必要的弯曲）
- 非关键路径上的主干道可以允许更多弯曲

### 3.4 输出

- 10×10的粗迷宫邻接矩阵
- 每对相邻屏之间是否有主干道连接的标记
- 主干道边界的具体开口位置（哪几格是主干道入口）

---

## 四、阶段二：区域类型划分

### 4.1 目的

将整个地图划分为不同性格的区域，让玩家在探索时感受到节奏变化，而不是均匀的迷宫体验。

### 4.2 区域类型定义

| 类型 | 名称 | 特点 | 密度 | 回路 | 死胡同 | 弯曲度 |
|------|------|------|------|------|--------|--------|
| A | 密集区 | 通道密、岔路多、容易兜圈子 | 高 | 多 | 低 | 中 |
| B | 蜿蜒区 | 通道弯、岔路少、死胡同多 | 中 | 少 | 高 | 高 |
| C | 瓶颈区 | 通道稀、岔路极少、关键通路 | 低 | 无 | 低 | 低 |
| D | 开阔区 | 局部打破网格，出现开放空间 | 特殊 | 特殊 | 低 | 不适用 |
| E | 隐藏区 | 被特殊墙壁包围，需战利品进入 | 特殊 | 无 | 无 | 不适用 |

### 4.3 算法步骤

**步骤1：确定起点屏和出口屏**
- 起点屏：随机选择，建议靠近地图边缘但不紧贴角落
- 出口屏：随机选择，需满足：
  - 与起点屏的粗迷宫距离（按主干道路径计算）≥ 4屏
  - 不在与起点屏直接相邻的4屏内

**步骤2：标记关键路径屏**
- 在粗迷宫中找到从起点屏到出口屏的唯一主干道路径
- 这条路径上的屏标记为“关键路径屏”

**步骤3：在关键路径上放置瓶颈区**
- 沿关键路径，每隔2-3屏放置一个瓶颈区（C型）
- 瓶颈区不要放在起点屏和出口屏本身
- 数量：10屏关键路径上放置约3-4个瓶颈区

**步骤4：填充其余屏的区域类型**
- 在剩余的屏中，随机分配类型，比例如下：
  - A型（密集区）：约35%
  - B型（蜿蜒区）：约30%
  - D型（开阔区）：约10%
  - E型（隐藏区）：约5%
  - 剩余20%留给C型之外的过渡区域（可以再次分配为A或B型）
- 分配时增加约束：同类型区域尽量不成片出现超过3屏（通过简单的邻域检查即可）
- E型（隐藏区）需满足：不与起点屏直接相邻，且不放在主干道关键路径上

**步骤5：微调**
- 检查从起点屏到出口屏，是否经过至少2个瓶颈区。不足则手动将路径上的A或B型改为C型
- 确保出口屏本身是A型或D型（让终点附近有足够的空间感，不是狭窄通道）

### 4.4 输出

- 10×10的区域类型矩阵，每个屏有明确的类型标签（A/B/C/D/E）

---

## 五、阶段三：各屏迷宫生成（带参数控制）

### 5.1 目的

为每一屏（10×16格）生成方格迷宫，生成参数根据该屏的区域类型动态调整。

### 5.2 基础生成算法

采用**递归回溯算法（深度优先搜索DFS + 随机化）**作为基础迷宫生成器。该算法生成的是完美迷宫（无回路、无孤立区域）。

基础算法步骤：
1. 将当前屏的所有格子视为独立的单元格，格与格之间有墙壁
2. 随机选择一个起始格，标记为已访问
3. 随机选择一个未访问的邻居，移除中间的墙壁，移动过去并标记为已访问
4. 递归重复，直到所有格子都被访问
5. 得到完美迷宫

### 5.3 按区域类型调整参数

在基础算法之上，通过以下参数控制每屏迷宫的特性：

#### 参数1：墙壁移除概率（控制密度）

在DFS过程中，除了移除必要的墙壁外，额外以概率P_extra随机移除尚未处理的墙壁。

| 区域类型 | P_extra | 效果 |
|----------|---------|------|
| A（密集区） | 0.25-0.35 | 通道密集，大量额外连接 |
| B（蜿蜒区） | 0.05-0.10 | 近乎完美迷宫，通道稀疏 |
| C（瓶颈区） | 0 | 绝对完美迷宫，仅有一条主路 |
| D（开阔区） | 特殊处理（见5.4） | 不适用 |
| E（隐藏区） | 0 | 完美迷宫，由特殊墙壁包围 |

#### 参数2：分支深度上限（控制死胡同数量）

在DFS递归时，限制递归深度。当达到深度上限时强制回溯，产生一个死胡同。

| 区域类型 | 分支深度上限 | 效果 |
|----------|-------------|------|
| A（密集区） | 8-12 | 死胡同较短较少 |
| B（蜿蜒区） | 2-5 | 大量短死胡同，探索代价小但频繁 |
| C（瓶颈区） | 不限制 | 极长通道，几乎没有死胡同 |
| D（开阔区） | 不适用 | 不适用 |
| E（隐藏区） | 不限制 | 与C类似 |

**实现方式**：
- 每次开始一个新分支时，计数器归零
- 每次递归深入一格，计数器+1
- 如果计数器达到上限，从当前格的可选邻居列表中排除“继续向前”的方向，优先选择横向的未访问邻居
- 如果不存在横向的未访问邻居，则自然形成死胡同并回溯

#### 参数3：方向延续权重（控制弯曲度）

在选择下一步移动方向时，不是均匀随机选择，而是给“与上一步方向相同”的邻居更高的权重。

| 区域类型 | 同向权重 | 异向权重 | 效果 |
|----------|---------|---------|------|
| A（密集区） | 1 | 1 | 方向随机，通道蜿蜒 |
| B（蜿蜒区） | 3 | 1 | 通道倾向直走，少拐弯 |
| C（瓶颈区） | 5 | 1 | 通道非常直，快速穿越 |
| D（开阔区） | 不适用 | 不适用 | 不适用 |
| E（隐藏区） | 1 | 1 | 与A类似 |

**实现方式**：
- 在邻居选择阶段，构建加权列表
- 例如当前方向为“右”，则“右”邻居在列表中重复出现3次（权重3），其他方向各1次
- 从加权列表中随机选取

### 5.4 D型（开阔区）特殊处理

开阔区不适用标准迷宫生成。改为以下处理：

**步骤1**：在该屏内，清空所有内部墙壁，形成一个10×16的完整空地

**步骤2**：在空地中放置若干独立的障碍物（1×1或2×2的墙壁块），位置随机但需满足：
- 不堵塞所有通路（保留至少一条从入口到出口的路径）
- 障碍物之间留有至少2格的间距
- 障碍物总数占该屏格子的15%-25%

**步骤3**：在障碍物旁放置宝箱，形成“看得见但需要绕路”的微谜题

**步骤4**：该屏的边界保留，与其他屏通过正常门口连接

### 5.5 E型（隐藏区）特殊处理

隐藏区同样适用标准迷宫生成，但需额外处理：

**步骤1**：正常生成完美迷宫

**步骤2**：将该屏所有与其他屏连接的边界墙壁，替换为“特殊墙壁”
- 特殊墙壁在视觉上与普通墙壁不同（如颜色、材质）
- 特殊墙壁不可通过，除非玩家使用指定战利品（如“越过障碍物”胶囊）

**步骤3**：在该屏内放置高价值宝箱（1-2个），作为冒险进入的奖励

### 5.6 屏间边界处理

各屏生成完毕后，需要处理相邻屏之间的边界：

**规则1：主干道边界**
- 如果两屏之间有主干道连接（根据阶段一的输出），则边界上移除2-3格宽的墙壁，形成宽阔通道
- 开口位置：优先选择边界的中点附近（横向边界中点、纵向边界中点），避免开在角落

**规则2：普通边界**
- 如果两屏之间没有主干道连接，则边界上随机移除1格宽的墙壁，形成普通门口
- 开口数量：1-2个
- 开口位置：随机，但避免两屏的开口在边界上直接对齐（制造一点偏移，增加探索感）

**规则3：隐藏区边界**
- E型屏与其他屏之间的边界，不自动移除任何墙壁
- 这些墙壁被标记为特殊墙壁

**规则4：边缘处理**
- 位于整个100×160迷宫最外圈的边界墙壁，全部保留为不可通过的边界墙

### 5.7 输出

- 完整的100×160迷宫网格，每个格子标记为“墙壁”或“通道”
- 屏间边界开口的准确位置
- 特殊墙壁的位置标记

## 六、阶段四：回路注入

### 6.1 目的

在阶段三生成的迷宫基础上，额外打通一些墙壁来创造回路。回路让玩家可以绕行、撤退、重新规划路线，减少挫败感，增加策略深度。

### 6.2 回路注入策略

回路注入不是均匀的，而是按区域类型差异化：

| 区域类型 | 每屏额外回路数 | 说明 |
|----------|---------------|------|
| A（密集区） | 3-5 | 大量回路，形成网状结构 |
| B（蜿蜒区） | 1-2 | 少量回路，保留探索张力 |
| C（瓶颈区） | 0-1 | 极少回路，保持关卡感 |
| D（开阔区） | 不适用 | 本身就是开放的 |
| E（隐藏区） | 0 | 不注入回路 |

### 6.3 算法步骤

**步骤1**：遍历迷宫中的所有墙壁

**步骤2**：对于每面内部墙壁（分隔两个通道格的墙壁），检查它是否满足以下条件：
- 该墙壁分隔的两个格子都是通道（不是墙壁格）
- 移除该墙壁后，不会将迷宫断成两个不连通的部分（可通过简单的连通性检查验证）
- 该墙壁所在屏的回路配额尚未用完

**步骤3**：如果条件满足，以概率P_loop决定是否移除该墙壁
- P_loop根据所在屏的区域类型查表确定
- A型：P_loop = 0.3-0.5
- B型：P_loop = 0.1-0.2
- C型：P_loop = 0-0.05
- D型、E型：P_loop = 0

**步骤4**：移除被选中的墙壁，更新迷宫网格

**步骤5**：更新该屏的回路计数，达到配额后停止该屏的回路注入

### 6.4 输出

- 更新后的迷宫网格（含回路）

---

## 七、阶段五：特殊元素放置

### 7.1 目的

在迷宫中放置出口、宝箱、特殊地形，赋予迷宫探索意义和玩法深度。

### 7.2 出口放置

**位置约束**：
- 出口所在屏已在阶段二中确定为出口屏
- 出口的具体格子位置：选择该屏内距离所有边界门口最远的格子（通过简单的距离计算：计算每个通道格到该屏所有出入口的最短路径长度的最大值）
- 这样可以确保玩家需要深入该屏才能找到出口，不会一进入就碰到

**出口标记**：
- 出口所在屏的所有通道格子，在视觉上做区分（如地面颜色变化），让玩家进入该屏时就能感知“这里不同”

### 7.3 宝箱放置

#### 7.3.1 宝箱总量和分布

| 区域类型 | 每屏宝箱数量 | 其中条件宝箱比例 |
|----------|-------------|-----------------|
| A（密集区） | 1-3 | 约30% |
| B（蜿蜒区） | 0-2 | 约50%（放在死胡同末端） |
| C（瓶颈区） | 0-1 | 约30% |
| D（开阔区） | 2-3 | 约40% |
| E（隐藏区） | 1-2 | 约20%（本身就是条件进入） |

#### 7.3.2 宝箱放置规则

**A型屏（密集区）**：
- 宝箱散落在不同通道上，彼此之间距离≥5格
- 至少1个宝箱放在“非必经之路”的侧通道上（需要玩家故意绕路）

**B型屏（蜿蜒区）**：
- 优先将宝箱放在死胡同的末端
- 如果该屏有2个宝箱，一个在浅层死胡同（离主路2-3格），一个在深层死胡同（离主路5格以上）
- 深层宝箱的价值应高于浅层宝箱（通过配置宝箱内容物来实现，不在本算法范围内）

**C型屏（瓶颈区）**：
- 宝箱放在主通道旁边，位置显眼但需要稍微偏离主路1-2格
- 由于瓶颈区火把压力大（绕路少），这里的宝箱可以设置得更有价值

**D型屏（开阔区）**：
- 宝箱放在障碍物周围，形成“看得见但需要绕路”的微谜题
- 不同宝箱分布在开阔区的不同角落

**E型屏（隐藏区）**：
- 宝箱放在屏内最深处，确保玩家需要探索整个隐藏区才能找到

#### 7.3.3 全局节奏控制

- 起点屏不放置宝箱（避免一开始就分散注意力）
- 出口屏可放置1个宝箱，作为最后的彩蛋
- 连续3屏以上的“无宝箱区”需要被打破——检查所有屏，如果某屏及其邻屏都没有宝箱，则在该屏随机补充1个

### 7.4 特殊地形放置

#### 7.4.1 地形类型

**残垣断壁（可通过的视觉墙壁）**：
- 视觉上看起来是破损的墙壁，但允许玩家通过
- 功能上等同于通道，但玩家需要“发现”它可通行
- 制造“我发现了一条秘密通道”的体验

**高消耗格（荆棘/浅水）**：
- 可以通过，但经过该格时火把消耗为正常的2倍
- 给玩家“抄近道但多耗资源”的抉择

**独石碑（纯视觉地标）**：
- 不能通过的装饰性地块，没有实际功能
- 帮助玩家建立空间认知
- 放在岔路口或区域中心

#### 7.4.2 放置规则

- 残垣断壁：每5-8屏放置1个，放在非主干道的墙上，连接两个通道
- 高消耗格：每3-5屏放置1-2格，放在“能明显缩短路径”的位置
- 独石碑：每2-3屏放置1个，放在岔路口或较宽阔的通道交汇处

### 7.5 起点放置

- 起点放在起点屏内
- 具体位置：选择靠近该屏与相邻屏连接的门口附近（方便玩家快速进入迷宫主体），但不要直接放在门口上

### 7.6 输出

- 完整的迷宫地图，包含所有特殊元素的位置标记
- 宝箱列表（坐标、类型、所在屏）
- 出口坐标
- 起点坐标

## 八、验证步骤

在算法全部执行完毕后，进行以下验证：

### 8.1 可达性验证

从起点格出发，使用BFS（广度优先搜索）遍历所有通道格：
- 出口格必须在可达集合中（确保迷宫有解）
- 所有宝箱必须在可达集合中（确保没有宝箱被孤立）
- 如果存在不可达的宝箱，移除该宝箱或在附近打通额外墙壁

### 8.2 路径长度估算

计算从起点到出口的最短路径长度（按通道格数量）：
- 最短路径应为总迷宫格数（通道格数）的30%-60%
- 如果太短（<25%），迷宫太简单，增加C型瓶颈区的长度
- 如果太长（>60%），迷宫可能太折磨，减少C型瓶颈区或增加回路

### 8.3 火把平衡估算（供后续调参参考，非算法本身）

根据最短路径长度，估算火把消耗：
- 假设每移动1格消耗1点火把
- 最短路径长度为L_min格
- 火把初始值建议设为L_min × 1.5至2.0倍
- 这样玩家有探索的余地，但不能无限兜圈

### 8.4 宝箱分布检查

- 检查是否存在连续4屏以上没有宝箱的区域，如有则补充
- 检查隐藏区是否有宝箱，如无则补充
- 检查起点屏是否有宝箱，如有则移除

## 十、算法伪代码（概览）

```
function GenerateMaze():
    // 阶段一
    coarseMaze = GenerateCoarseMaze(10, 10)           // 粗迷宫
    backboneBorders = ExtractBackboneBorders(coarseMaze)
    
    // 阶段二
    startScreen = SelectStartScreen()
    exitScreen = SelectExitScreen(startScreen, coarseMaze)
    zoneTypes = AssignZoneTypes(coarseMaze, startScreen, exitScreen)
    
    // 阶段三
    fullMaze = EmptyGrid(100, 160, fill=WALL)
    for each screen (row, col) in 0..9 × 0..9:
        type = zoneTypes[row][col]
        screenMaze = GenerateScreenMaze(type)         // 带参数控制
        PlaceScreenMaze(fullMaze, screenMaze, row, col)
    
    // 处理屏间边界
    ProcessScreenBorders(fullMaze, backboneBorders, zoneTypes)
    
    // 阶段四
    InjectLoops(fullMaze, zoneTypes)
    
    // 阶段五
    PlaceExit(fullMaze, exitScreen)
    PlaceTreasures(fullMaze, zoneTypes)
    PlaceSpecialTerrain(fullMaze, zoneTypes)
    PlaceStartPoint(fullMaze, startScreen)
    
    // 验证
    ValidateReachability(fullMaze, start, exit)
    EstimatePathLength(fullMaze, start, exit)
    
    return fullMaze
```
