# 迷宫生成算法 v6.0 — 隐藏房间与通道

## 1. 概述

在 v5（基于房间/走廊的随机生成）基础上，新增**隐藏房间（Hidden Room）**系统。隐藏房间位于主路径之外，在游戏中被渲染为普通墙体，只有玩家找到并走进隐藏的通道入口后，房间才会"揭晓"。

## 2. 数据结构变更

### 2.1 `CELL_TYPE_V5` → `CELL_TYPE_V6`

```javascript
const CELL_TYPE_V6 = {
    // 原有类型（保持不变）
    WALL: 0,
    FLOOR: 1,
    CHEST: 2,
    EXIT: 3,
    RUIN: 4,
    HIGH_COST: 5,
    MONUMENT: 6,
    ROOM_FLOOR: 7,
    ROOM_WALL: 8,
    DOOR: 9,
    SPECIAL_WALL: 10,

    // v6 新增类型
    HIDDEN_WALL: 11,     // 隐藏房间的外墙，未揭晓时渲染为普通墙
    HIDDEN_FLOOR: 12,    // 隐藏房间的内部地板，未揭晓时渲染为普通墙
    HIDDEN_PASSAGE: 13   // 通道格，未揭晓时渲染为普通墙，玩家走入时触发揭晓
};
```

### 2.2 `ROOM_TYPE_V6`

```javascript
const ROOM_TYPE_V6 = {
    // ... 保持 v5 所有类型不变 ...
    HIDDEN: 'hidden'     // 保留，但行为重新定义
};
```

### 2.3 `RoomV6` 新增字段

```javascript
class RoomV6 {
    // ... 继承 v5 RoomV5 结构 ...
    this.hiddenPassage = null;  // { doorTile, cells: [], width: 1|2 }
    this.isRevealed = false;    // 运行时使用，生成阶段始终为 false
}
```

## 3. 生成器阶段变化

v6 新增 **1 个阶段**（放置隐藏房间），修改 **3 个阶段**（走廊、物品放置、类型转换、验证）。

### 3.1 阶段总览

```
v5:   B1 → B2 → B3 → B4 → B5 → B6 → B7 → B8 → B9 → B10 → CONV → THICK
v6:   B1 → B2 → B3 → B4 → B5 → B6 → B7 → B8 → B9  → B10 → B11 → CONV → THICK
 新增:
  B11: placeHiddenRooms   — 将 HIDDEN 类型房间布设到非活跃区块
```

### 3.2 B11: placeHiddenRooms（新增）

**时机**：在 B10（validate）之后、CONV（convertCellTypes）之前执行。

#### 3.2.1 房间选址

1. 收集所有**未被任何房间占用**的非活跃区块（`isActive === false` 的 blocks）
2. 筛除边缘区块（第 0 行/列、最后 1 行/列），确保隐藏房间不完全贴边
3. 从剩余区块中随机选择 `hiddenRoomCount` 个
   - `hiddenRoomCount = Math.max(1, Math.floor(inactiveBlockCount * 0.15))`（约 15% 的非活跃区块）
   - 最少 1 个，最多 4 个

#### 3.2.2 房间布局

每个选中的区块，在其内部生成一个房间：

```
区块尺寸: x × x（由 v5 算法决定，通常 14～20）
房间尺寸: width = x - 4, height = x - 4（留出 2 格边距）
房间位置: 居中放置，即
  gridRow = block.gridRow + 2
  gridCol = block.gridCol + 2
```

房间内部填充 `HIDDEN_FLOOR`（12），房间边界填充 `HIDDEN_WALL`（11）：

```javascript
for (let r = top; r <= bottom; r++) {
    for (let c = left; c <= right; c++) {
        if (r === top || r === bottom || c === left || c === right) {
            this.globalGrid[r][c] = CELL_TYPE_V6.HIDDEN_WALL;
        } else {
            this.globalGrid[r][c] = CELL_TYPE_V6.HIDDEN_FLOOR;
        }
    }
}
```

可选：在 `HIDDEN_FLOOR` 区域内放置 0～2 根内部柱子（`HIDDEN_WALL`），增加视觉效果。

#### 3.2.3 通道选址

1. 以隐藏房间的几何中心为起点，向 4 个方向扫描
2. 找到离隐藏房间最近的已存在 `FLOOR` 格（即现有走廊/房间的路径）
3. 如果最近距离 > 15 格，放弃该房间（太偏远没有实际意义）

#### 3.2.4 通道挖掘

从隐藏房间边界到最近的 `FLOOR` 格之间挖一条通道：

```
通道宽度: 随机 1 格或 2 格（基于 tile 图片限制）
通道长度: 最短路径（使用 A* 或简单方向直线）
通道填充: HIDDEN_PASSAGE（13）
```

**通道转弯限制**：通道必须是直的（水平或垂直），不能转弯。如果需要转弯，使用 L 形通道（最多 1 个弯），即先水平后垂直或先垂直后水平。

通道的每个格子设为 `HIDDEN_PASSAGE`，确保两侧依然是 `WALL`。

#### 3.2.5 门 tile 标记

在通道与隐藏房间的连接点（即房间出口处），记录门的信息：

```javascript
room.hiddenPassage = {
    entranceGX: entranceGX,   // 通道与房间连接处的格子坐标
    entranceGY: entranceGY,
    doorwayGX: doorwayGX,     // 通道与走廊连接处的格子坐标（对玩家而言的"入口"）
    doorwayGY: doorwayGY,
    width: 1 | 2,             // 通道宽度
    direction: 'up'|'down'|'left'|'right',  // 通道从房间出发的方向
    cells: [...]              // 通道所有格子坐标
};
```

门 tile 的选择（由渲染层基于通道宽度和方向决定）：

| 通道宽度 | tile 文件 |
|---------|-----------|
| 1 格 | `tile_0009.png`（无门板门洞） |
| 2 格左 | `tile_0010.png` |
| 2 格右 | `tile_0011.png` |

> 注：tile_0021～0023（门全开）、0033～0035（门半开）、0045～0047（门全关）在当前版本保留加载，供后续"开门动画"玩法使用。

#### 3.2.6 宝箱放置

隐藏房间内部放置 1～2 个 `CHEST`（与 v5 B9 逻辑相同）：

```javascript
// 宝箱数量
case ROOM_TYPE_V6.HIDDEN: chestCount = rng.nextInt(1, 2); break;
```

### 3.3 修改 B7: 走廊生成（_generateCorridorPaths）

在 `_generateCorridorPaths()`（v5 第 970-1035 行）中，初始化网格时需要**保留** `HIDDEN_WALL` / `HIDDEN_FLOOR` / `HIDDEN_PASSAGE` 格，不被走廊覆盖。

修改 `_generateCorridorPaths()` 初始化逻辑：

```javascript
// v6 修改：走廊不能覆盖隐藏房间
for (const room of this.rooms) {
    if (room.type !== ROOM_TYPE_V6.HIDDEN) {
        // 原有的房间绘制逻辑（ROOM_FLOOR / ROOM_WALL）
        this._drawRoomOnGrid(room);
    }
    // HIDDEN 房间不在此处绘制，由 B11 阶段专门处理
}
```

A* 寻路时，`HIDDEN_WALL` / `HIDDEN_FLOOR` / `HIDDEN_PASSAGE` 视为不可通行（防止走廊穿入隐藏房间）：

```javascript
// 在 A* 的邻居检查中
if (grid[nr][nc] === CELL_TYPE_V6.WALL ||
    grid[nr][nc] === CELL_TYPE_V6.HIDDEN_WALL ||
    grid[nr][nc] === CELL_TYPE_V6.HIDDEN_FLOOR ||
    grid[nr][nc] === CELL_TYPE_V6.HIDDEN_PASSAGE) {
    continue;
}
```

### 3.4 修改 B10: 验证（_stage10_validate）

BFS 可通行性验证需要将 `HIDDEN_FLOOR` 视为可通行格，否则验证会认为隐藏房间不可达而报错：

```javascript
// v6 修改：HIDDEN_FLOOR 视为可通行
const startCell = this.globalGrid[sr]?.[sc];
if (startCell !== undefined &&
    startCell !== CELL_TYPE_V6.WALL &&
    startCell !== CELL_TYPE_V6.SPECIAL_WALL &&
    startCell !== CELL_TYPE_V6.HIDDEN_WALL &&
    startCell !== CELL_TYPE_V6.HIDDEN_PASSAGE) {  // 注意：HIDDEN_FLOOR 是可通行的
    queue.push({ row: sr, col: sc });
    visited.add(`${sr},${sc}`);
}

while (queue.length > 0) {
    // ...
    if (cell === CELL_TYPE_V6.WALL ||
        cell === CELL_TYPE_V6.SPECIAL_WALL ||
        cell === CELL_TYPE_V6.HIDDEN_WALL ||
        cell === CELL_TYPE_V6.HIDDEN_PASSAGE) continue;  // HIDDEN_FLOOR 不在此阻止
    // ...
}
```

房间可达性检查：HIDDEN 类型的房间不要求在主路径 BFS 中可达（隐藏房间本来就是隐藏的），予以跳过：

```javascript
for (const room of this.rooms) {
    if (room.type === ROOM_TYPE_V6.HIDDEN) continue;  // 跳过隐藏房间
    // ... 原有的可达性检查 ...
}
```

### 3.5 修改 CONV: 类型转换（_convertCellTypes）

v5 原逻辑将所有中间类型（7～10）转为最终类型。v6 需要保留隐藏房间相关类型在最终 grid 中：

```javascript
_v6_convertCellTypes() {
    const convert = {
        [CELL_TYPE_V6.ROOM_FLOOR]: CELL_TYPE_V6.FLOOR,
        [CELL_TYPE_V6.ROOM_WALL]: CELL_TYPE_V6.WALL,
        [CELL_TYPE_V6.DOOR]: CELL_TYPE_V6.FLOOR,
        [CELL_TYPE_V6.SPECIAL_WALL]: CELL_TYPE_V6.WALL
        // HIDDEN_WALL(11), HIDDEN_FLOOR(12), HIDDEN_PASSAGE(13) 不做转换
    };
    for (let r = 0; r < this.mapSize; r++) {
        for (let c = 0; c < this.mapSize; c++) {
            const v = this.globalGrid[r][c];
            if (convert[v] !== undefined) this.globalGrid[r][c] = convert[v];
        }
    }
}
```

### 3.6 修改墙厚保障（_ensureWallThickness）

在 `isWall` 检查中，`HIDDEN_WALL` 和 `HIDDEN_PASSAGE` 应视为墙：

```javascript
const isWall = (r, c) => {
    return r >= 0 && r < this.mapSize && c >= 0 && c < this.mapSize &&
           (this.globalGrid[r][c] === CELL_TYPE_V6.WALL ||
            this.globalGrid[r][c] === CELL_TYPE_V6.HIDDEN_WALL);
};
```

`HIDDEN_FLOOR` 不应被墙厚算法改成 `FLOOR`。在墙厚保障循环中跳过这些格子：

```javascript
if (this.globalGrid[r][c] !== CELL_TYPE_V6.WALL) continue;
// HIDDEN_WALL / HIDDEN_FLOOR 不参与墙厚优化
```

## 4. Run-time 揭晓机制

### 4.1 触发条件

在 `mist.html` 的 `checkBoundaryCollision()` 或 `handleCellTransition()` 中，当玩家完成一次移动后，检查当前格子：

```javascript
handleCellTransition() {
    // ... 原有逻辑 ...

    // v6: 检查是否走入隐藏通道
    const cell = this.map.globalGrid[gy][gx];
    if (cell === CELL_TYPE.HIDDEN_PASSAGE) {
        this.revealHiddenRoom(gx, gy);
    }
}
```

### 4.2 揭晓流程

```javascript
revealHiddenRoom(startGX, startGY) {
    // BFS 扫描与当前格连通的所有 HIDDEN_PASSAGE / HIDDEN_FLOOR / HIDDEN_WALL
    const toReveal = [];
    const queue = [{ gx: startGX, gy: startGY }];
    const visited = new Set();

    while (queue.length > 0) {
        const { gx, gy } = queue.shift();
        const key = `${gx},${gy}`;
        if (visited.has(key)) continue;
        visited.add(key);

        const cell = this.map.globalGrid[gy][gx];
        if (cell === CELL_TYPE.HIDDEN_PASSAGE ||
            cell === CELL_TYPE.HIDDEN_FLOOR ||
            cell === CELL_TYPE.HIDDEN_WALL) {
            toReveal.push({ gx, gy });

            for (const [dx, dy] of [[0,1],[0,-1],[1,0],[-1,0]]) {
                const nx = gx + dx, ny = gy + dy;
                if (nx >= 0 && nx < TOTAL_COLS && ny >= 0 && ny < TOTAL_ROWS) {
                    queue.push({ gx: nx, gy: ny });
                }
            }
        }
    }

    // 批量转换
    for (const { gx, gy } of toReveal) {
        const cell = this.map.globalGrid[gy][gx];
        if (cell === CELL_TYPE.HIDDEN_FLOOR) {
            this.map.globalGrid[gy][gx] = CELL_TYPE.PATH;
        } else if (cell === CELL_TYPE.HIDDEN_WALL) {
            this.map.globalGrid[gy][gx] = CELL_TYPE.WALL;
        } else if (cell === CELL_TYPE.HIDDEN_PASSAGE) {
            this.map.globalGrid[gy][gx] = CELL_TYPE.PATH;
        }
    }

    // 标记该房间已揭晓
    this.markExplored(gy, gx);  // 揭晓的区域立即在迷雾中可见
}
```

### 4.3 揭晓效果

揭晓后：
- 隐藏房间的 `HIDDEN_FLOOR` → `PATH`，变为正常可通行地板
- 隐藏房间的 `HIDDEN_WALL` → `WALL`，仍然是墙（但不再隐藏）
- 通道的 `HIDDEN_PASSAGE` → `PATH`，变为正常走廊
- 整片区域标记为已探索，迷雾散去

### 6.2 渲染规则

在 `render()` 方法中，`HIDDEN_FLOOR` / `HIDDEN_WALL` / `HIDDEN_PASSAGE` 全部渲染为普通 `WALL`，玩家看不到任何区别。

在揭晓之后（类型已被替换为 `PATH` / `WALL`），按正常的 tile 渲染逻辑绘制。
